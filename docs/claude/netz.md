# Netz, Koop, Lobby, Gemischt

Aus CLAUDE.md ausgelagert; der Hook `.claude/hooks/thema.py` blendet diese Notiz automatisch ein, sobald ein Thread passende Dateien anfasst.

- Netz: `scripts/net/` (`coop_sync.gd` gemeinsames Feld, `net_sync.gd`/`remote_field.gd`/`net_panel.gd` Zuschauen im Modus „jeder sein Feld“). Gemischt: in der Lobby hat jeder Spieler eine Feldnummer, gleiche Nummer = Koop-Gruppe (`Net.start_session(map, groups)`, der Erste der Gruppe rechnet, Befehle laufen über den Host weiter, `Net.group_peers()`); Test `tools/run_tests.sh gemischt` (drei Prozesse). Modi hängen sich an Koop und Spielstand über `coop_snapshot`/`save_extra`/`new_tower` im Spiel an (Beispiel eeveTD).

- Latenz (2026-11-10): Koop-Bewegungsstrom `_coop_enemies` verwendet ENet-Kanal 1 (`unreliable_ordered`), getrennt von anderen RPC-Strömen. Akzeptierte Koop-Befehle setzen in `CoopSync` Struktur- und Zustandsuhr auf 0, damit im nächsten Frame bestätigt wird. Snapshot-/Bewegungsraten bleiben erhalten; Tests `koop syscoop gemischt`.

- Bollwerk-Koop: `HdCoop` nutzt bestehende Lobby/Koop-Gruppen für 1–8 Spieler. Host simuliert, jeder besitzt eigenen Helden/Shop/Skills; Befehle laufen validiert im jeweiligen Spieler-Kontext. M1/WASD/Mausbewegung über sequenzierte 30-Hz-Eingaben (Kanal2), 300-ms-Ausfallsicherung. Clients sagen Bewegung/Ausweichen lokal voraus und gleichen unbestätigte Eingaben ab. 20-Hz-Frames komprimiert mit Zstd, 900-Byte-Fragmente auf ungeordnetem Kanal3; ganze alte/unvollständige Frames verworfen, verlässlicher Vollstand alle 0,5 s. CC, Konstrukttypen/Besitzer, Warnflächen, Tageszeit, Event-/Endgebiet und Inventare repliziert. Tests: `heroescoop` echte 2 Prozesse; `heroesnetstate` acht Helden + Verlust/Reihenfolge/Realm-Wechsel. Kein SaveGame-Format für Bollwerk-Koop implementiert.
