# Gemeinsame Spielsysteme (scripts/systems/)

Umbau ab 2026-11-08 (Lukas: „Spielsysteme unabhängig von den Modi, Modi modular aus den Systemen bauen, so viel wie möglich mit Skripten“). Plan in 7 Etappen: 1 Werkzeuge, 2 run_record + difficulty, 3 targeting, 4 economy + save, 5 waves, 6 coop + inventory, 7 build + controls + Aufräumen. Übersicht wer was nutzt: `docs/systeme.md` (erzeugt).

- Ein System = `scripts/systems/<name>/<name>.gd` (`extends GameSystem`, Knoten am Spiel) + Basiswerte `<name>.json`. Reine Bibliotheken mit `static func` (Leveling) liegen auch dort, werden aber nicht als Knoten angelegt.
- Katalog `scripts/systems/katalog.json`: Titel, Etappe, `eigen` (Funktionsnamen, an denen man erkennt, dass ein Modus das System noch selbst baut), `klasse`, dazu `_modi` (welche Dateien zu welchem Modus gehören) und `_verboten` (Modus-Namen, die in Systemen nicht vorkommen dürfen).
- Modus wählt Systeme in `data/modes.json` → `systems`; Einstellungen je Modus `system_cfg.<name>`. **Kaskade wie CSS (Lukas 2026-11-08):** Basiswerte des Systems, darüber die Modus-Daten; was der Modus angibt, gewinnt immer, Dictionaries werden tief gemischt, Listen ersetzt (`SystemHost.config`/`cascade`). Spielgefühl-Unterschiede zwischen Modi also als Modus-Daten, nicht als Code-Weiche.
- `SystemHost.attach(game, mode_id)` hängt die Systeme als Kind-Knoten an und füllt `game.systems`. Ein System ruft Modus-Eigenes nur über `hook("name", args, ersatz)` (game hat die Funktion → aufrufen, sonst Ersatzwert).
- Werkzeug `tools/systeme.py`: `matrix [--md]`, `pruefen` (läuft in den Tests als `systeme_pruefen`), `neu <name> [--test]`, `umziehen <quelle.gd> <system> <fkt,…> [--schreiben]` (Codemod: Funktionen ins System, Mitglieder des Spiels bekommen `game.`, `var x := game.…` wird `=`, in der Quelle bleibt eine Weiterleitung `## Weiterleitung → System`; meldet Überschreibungen in Unterklassen und Aufrufer), `weiterleitungen [--umstellen] [--entfernen]`.
- Etappe 2 (fertig): `run_record` (Run-Ende/Abbruch ins Profil für alle 7 Modi: `finish(info, stats, fixed)`, `abort(info, fixed)`, Haken profile_mode/profile_extra/debug_run, Profil-Schlüssel cfg.profile für Maul/Bollwerk/Survivors) und `difficulty` (Liste aus `source` session/rules/cfg, `index/current/label/count/top/take_ascension/ascension_mods/apply_ascension`; `ascension.gd` liegt daneben als Bibliothek). game.gd gibt die alten Namen (`difficulty_index`, `diff_rules` …) ans System weiter; eeve/rg/youtd haben keine eigenen mehr. Welche Systeme ein Spiel bekommt: `system_mode()` (game.gd „gemtd“, Unterklassen überschreiben), Maul/Bollwerk/Survivors fest in `_init`.
- Etappe 3: `targeting` für alle 7 Modi: `find_targets(t, n)`, `find_targets_in(t, r, n)`, `enemies_in_radius(p, r)`, `nearest(p, r, skip)`. Gegnerform je Modus über cfg `position` (pos/xz/global_xz) und `radius` (leer/radius/half_size). Alte Namen in game.gd, maul, hd (`nearest_enemy`), sv (`nearest`, `in_radius`) sind Weiterleitungen. Deckung (`is_covered`, `free_stretch`, `idle_speed_factor`) bleibt Regel des Modus, im Katalog unter build.
- Etappe 4: `economy` (`earn(amount, p)` mit Einkommens-Faktor und Bruchteilen, `add(amount, p)` direkt, `income_factor(wave)`; GemTD/YouTD `income_from_balance`, eeveTD/Randgruppen voller Faktor als Basis, Maul `split_unowned: false`). Bollwerk/Survivors haben eigene Geldbörsen (Held, Plattform). `save`: `save_game.gd` (class SaveGame) liegt jetzt unter `scripts/systems/save/`, Haken `save_extra`/`load_extra`/`save_mode`; YouTD/Maul behalten ihre eigenen Spielstände.
- Etappe 5: `waves` = Spawn-Warteschlange `drain(queue, timer, delta, spawn, interval)` (holt verspätete Gegner nach) und Auto-Welle (`has_auto`/`auto_due`/`next_now`, cfg `auto.enabled/command/due`; eeveTD/Randgruppen `build_after_first` + `start_level`, YouTD Haken `auto_wave_rule` + `next_wave`). Welleninhalt, Start und Spawn eines Gegners bleiben Haken der Modi. YouTD (mehrere Spawner mit Zufallsabstand) und Maul (Stapel-Spawn mit Obergrenze) haben noch eigenes `_process_wave`. Bot-Läufe `tools/testlauf.sh alle --stufen=2 --seeds=1,2` vorher/nachher identisch (Sicherung /mnt/project-files/systeme/vorher_waves.jsonl).
- Etappe 6: `coop` für alle Modi auf game.gd: `coop_sync.gd` (class CoopSync) liegt jetzt in `scripts/systems/coop/`. Erlaubte Befehle = cfg `commands` + `extra_commands`; der Modus-Stand für Mitspieler kommt aus cfg `fields` (Name → Spielvariable oder `{var, ceil, keys}`) und `tower_meta` (z. B. `spent`), Rest über Haken `coop_extra()`/`coop_applied(d, changed)`; Weggehen `set_away(p, away)` → Haken `on_player_away`. `inventory`: `setup_drop()` richtet InvWorldDrop für game.gd und Maul ein (cfg `command`, `tower_ref` ref/cell), `drop(t, data)`, `free_hint(t)`, `slots(t)` (Haken `item_slots`), `move(la, k, lb, j)` (WC3-Tausch/Verschieben, eeveTD und Maul). Welche Items wohin dürfen, bleibt Regel des Modus (Haken `inv_drop_reason`/`inv_drop_hint`, `move_reason`).
- Etappe 7: `build` = Belegen `occupy(a, on, solid)` und `can_place(a, any_zone)` (Haken `build_rule(a)`, cfg `solid`: YouTD false, Gegner auf festen Wegen), Lichtpfad/„alle Wege“ (`set_path_lights`, `set_show_all_paths` → Haken `show_paths`), Deckung (`is_covered`, `free_stretch`, `free_stretches`, `cover_signature`, `idle_speed_factor`; cfg `cover` towers/rule – Maul Haken `cover_rule` für leere Gebiete –, `idle_speed` from balance/rules/value). `controls` = cfg `box_select` (nur GemTD zieht Rahmen um Steine) und `set_speed(f)` mit cfg `speeds` (Befehl speed in game.gd und Maul). Klick, Hover, Auswahl und Pause bleiben Haken der Modi. `save` hat jetzt den Code (save_game, save_coop, autosave, drop_autosave; Haken `save_kind`). Katalog `modusregel` {modus: Grund} = bewusst eigene Umsetzung (Matrix zeigt „Modusregel“, Gründe unten in docs/systeme.md). Codemod `umziehen` setzt jetzt auch `self` → `game` und Enums des Spiels → `game.<Enum>`.
- Katalog `haken`: Funktionen, die ein Modus dem System anbietet; zählen in der Matrix nicht als „eigen“. Eine Funktion, die nur `systems.<name>.…` ruft, auch nicht.
- Tests: Sammeltest `tests/systems/systeme_test.gd` (Kopf `## Modi:` hält `systeme.py neu` aktuell), eigener Test je System, sobald es Code bekommt (`neu --test`). Testauswahl: Änderung unter `scripts/systems/<name>/` testet die Modi mit diesem System (tools/test_auswahl.py).
